# Задача #1: базовые справочники — депутаты и комиссии

**Описание**: реализовать две независимые справочные сущности —
`Deputy` (депутат) и `Commission` (комиссия) — с CRUD-эндпоинтами.
Это фундамент, от которого зависят задачи #2 и #3.

**Критерии приёмки**:
- Модель `Deputy`: `id`, `full_name` (2–255 симв., обязательно),
  `party`, `election_district`, `is_active`, `created_at`.
- Модель `Commission`: `id`, `name` (уникально), `description`,
  `created_at`.
- CRUD-эндпоинты для обеих сущностей (`GET`/`POST`/`PATCH`/`DELETE`).
- Дублирующееся название комиссии — `409 Conflict`.
- Некорректное тело запроса — `422`.
- Миграция Alembic создаёт таблицы `deputies`, `commissions`.
- Тесты покрывают CRUD, валидацию и конфликт по имени комиссии.

**Ветка**: `feature/deputies-commissions`

**Статус**: реализовано, смержено в `main`.
