# INCIDENT-001: БД остановлена, а система считает себя здоровой

| | |
|---|---|
| Окружение | staging (версия до ЛР8) |
| Затронутый компонент | связь приложения с PostgreSQL; проверки здоровья |
| Влияние | все операции API отвечают 500, веб-интерфейс не работает |
| Обнаружено | при подготовке ЛР8, сценарий «остановка базы данных» |
| Статус | исправлено, процесс изменён (см. «Что изменили») |

## Что произошло

Контейнер PostgreSQL остановили (`docker stop city-duma-staging-db-1`).
Приложение продолжило работать, но каждая операция с данными падала с ошибкой
подключения. При этом:

- `/health` отвечал `200 {"status": "ok"}`, Docker показывал контейнер `healthy`;
- проверка релиза ЛР6 (`make release-check`) на первом шаге (`/health`)
  ошибку не видела — проблема всплывала только на сценарии с данными;
- ни журнала, ни метрики, по которым это было бы видно сразу, не было.

## Как подтвердили причину

1. `docker ps` — `db` в статусе `Exited`, `app` — `healthy`.
2. `curl /deputies` → 500, `curl /health` → 200: процесс жив, не работает зависимость.
3. Журнал приложения — ошибки подключения к `db:5432`.

## Почему не обнаружили раньше

`/health` проверял только, что процесс отвечает (liveness), а не что
приложение может работать (readiness). Других сигналов о состоянии БД не было.

## Что изменили (ЛР8, п.14)

| Барьер | Где |
|---|---|
| адрес `/ready`: выполняет `SELECT 1`, при ошибке 503 | `app/main.py` |
| метрика `app_db_up` и событие журнала `db_unavailable` | `app/main.py`, `app/observability/` |
| оповещение `AppDatabaseDown` (1 минута), раздел в RUNBOOK | `monitoring/prometheus/alerts.yml`, `docs/RUNBOOK.md` |
| проверка релиза требует `/ready` = 200 — выпуск с недоступной БД не принимается | `scripts/release_check.py` |
| тесты: `/ready` и `app_db_up` при «упавшей» БД, проверка релиза при недоступной БД, правило `AppDatabaseDown` | `tests/test_observability_api.py`, `tests/unit/test_release_check.py`, `alerts.test.yml` |
| подключение к БД с таймаутом 3 с — `/ready` отвечает сразу, а не висит | `app/database.py` |

`/health` намеренно оставлен проверкой только процесса: по нему Docker решает,
здоров ли контейнер. Если бы он зависел от БД, остановка БД вызывала бы
бесполезные перезапуски приложения.

## Как проверить, что теперь обнаруживается

```
docker stop city-duma-staging-db-1
curl -i http://192.168.58.139:8800/ready     # 503 {"database": "unavailable"}
make release-check                           # падает на шаге /ready
# через минуту: Prometheus → Alerts → AppDatabaseDown (firing)
docker start city-duma-staging-db-1
```
